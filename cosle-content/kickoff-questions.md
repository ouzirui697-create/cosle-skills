# Step 0 反问问题清单

> 任何 Cosle 文章动笔前必跑这一步。用 `AskUserQuestion` 工具,一次最多 3-4 个问题分轮次问。
> 不允许跳过此步。即使用户给了主题,也必须确认参考文章 / 选题方向 / 字数 / 引流强度 / 承接关系五件事。

---

## 第一轮(必问)

### Q1 · 系列承接

**问法**:这是 Cosle 公众号 / 小红书第几篇?上一篇有没有「下期预告」要兑现?

**为什么问**:Cosle 内容是连续系列,#001 已发 Alexa for Shopping 三层架构,#002 已发 Listing 5 类信息。每篇文末都有「下期预告」,下一篇必须兑现,否则品牌可信度受损。

**默认选项**:
- A. 兑现上一篇的「下期预告」
- B. 蹭最新行业动向(用户提供新闻源)
- C. 卖家高频提问反推(从客户咨询里抽取)
- D. 真实诊断案例反推(选一个客户的发现展开)

---

### Q2 · 参考文章

**问法**:有没有想参考的文章?(可以粘贴正文或描述结构要点)

**为什么问**:用户经常说「写得像这篇」。微信公众号链接(mp.weixin.qq.com)WebFetch 大概率拿不到(反爬验证页),必须让用户直接粘贴正文。

**3 种来源处理方式**:
- 微信公众号链接 → **必须让用户粘贴正文**,不要凭标题猜测
- 小红书 / 头条 / 知乎 → 同样要求粘贴
- 用户口述结构要点 → 接受,但要复述给用户确认理解一致

**学/不学清单**(参考文章吸收时严格执行):

| 学 | 不学 |
|---|---|
| 结构、节奏、自问自答 | 吐槽口吻、个人化"我"过密 |
| 数据钩子(具体百分比) | 危机词、夸大叙事 |
| 错误示范 vs 正确示范的对比手法 | 对友商调侃 |
| 板块分界线视觉断点 | 戏谑梗(神仙打架/查无此人) |
| 4 类 / 5 类信息框架 | 「翻译一下」式个人化口吻 |

---

### Q3 · 字数 + 引流强度

**问法**:字数和引流强度?

**默认选项**:
- A. 1500-1800 字 · 软引流(文末邀请扫码,不催)
- B. 2500-3000 字 · 干货为主(引流仅最后一段)
- C. 1200-1500 字 · 短钩子(节奏快、适合朋友圈转发)
- D. 小红书 11 张图卡 + 公众号 2500 字(同选题双渠道)

**经验**:第一篇用 A 建立调性,第二、三篇用 B 立专业感,日常更新可用 C。双渠道(D)成本高但触达最广。

## 第二轮(按需问)

### Q4 · 真实诊断案例

**问法**:这篇要不要用真实诊断案例?用哪个客户?数字是否能公开?

**为什么必问**:Cosle 文章的核心可信度来自真实诊断案例。但案例数字(命中率、ACoS、订单占比等)必须经客户同意才能公开,否则只能用定性描述(「显著上升」)。

**3 种处理**:
- 沿用首发版案例(浴室扶手 / 88.9% 误归类)— 已脱敏可继续用
- 新案例 — 必须确认脱敏粒度(品类描述?品牌名?ASIN?数字精度?)
- 不用案例 — 只讲方法论(适合短钩子文)

> ⚠️ **绝对禁止**:编造数字、估算数字、把 A 客户的数字套到 B 客户身上。
> 未确认数字一律用 `[X]` 占位 + ⚠️ 警告,在文末「待用户确认事项」列出。

---

### Q5 · 文末引流方式

**问法**:文末怎么引流?

**默认选项**:
- A. 关键词回复「自查」+ 扫码加微(标准款)
- B. 仅扫码加微(短文用)
- C. 只放品牌签名,不引流(蹭热点的纯曝光文)
- D. 引流到诊断报告样例(对已扫码加微的卖家发样本)

**渠道差异**:
- 公众号:四种都可用
- 小红书:**所有 CTA 一律禁用**(平台规则)。最多放「关于 Cosle」品牌签名段,作为内容创作者身份出现。

---

### Q6 · 视觉风格调整

**问法**(可选,仅当系列做久了需要换风格时):
- 沿用 v4 品牌封面(深灰底 + Cosle 居中)
- 换内容封面(主标 + 信息维度,如 v2.0 listing 那版)
- 新做一版(用户描述)

## 反问对话模板(直接复用)

```
我开始动笔之前,需要先把几件事和你对齐。
[AskUserQuestion 第一轮:Q1 + Q2 + Q3]

[收到答复后,根据缺口问第二轮]
[AskUserQuestion 第二轮:Q4 + Q5]

[全部对齐后]
好,信息够了。我先把文章骨架列出来你过一眼,确认 OK 后再落稿。
[输出 5 节骨架的纲要,用户确认]

[确认后才开始 Step 3 落稿]
```

## 反问失败的常见情形

| 情形 | 处理 |
|---|---|
| 用户说「你自己定」 | 提供 2-3 个具体选项让对方挑,不要自由发挥 |
| 用户给了微信链接但 WebFetch 失败 | 明确说「微信反爬,你直接粘贴正文给我」 |
| 用户给了案例数字但来源模糊 | 反复确认「这个数字是哪个客户、哪个时间段、是否允许公开」 |
| 用户说「和上次一样」 | 反查上一次的对话记录或 reference-examples/,复述一遍确认 |
| 用户催「直接写吧别问了」 | 仍要至少确认 1 个核心信息(选题方向),其余用默认,文末标注「未对齐的假设」 |

---

## Auto Mode 例外

如果当前会话已开启 Auto Mode(自动模式),仍要执行 Step 0,但可以:
- 把多个问题合并成一个 AskUserQuestion,选项尽量穷举
- 对参考文章和案例数字两项,如果用户上一轮已经给过,不再问

但**绝对不能**完全跳过 Step 0,因为没有信息对齐的文章必定踩品牌雷区。
