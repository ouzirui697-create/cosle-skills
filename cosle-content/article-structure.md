# Cosle 文章 5 节骨架(写作骨架)

> 不论公众号长文 / 小红书图卡 / 双渠道,都用这一套骨架。每节有固定职责,不允许打乱顺序。

## 骨架全景

```
┌─────────────────────────────────────────────┐
│ 摘要框(浅灰底 + 红色左边条)               │  ← 仅公众号
└─────────────────────────────────────────────┘

┌─ 1 · 开篇钩子 ──────────────────────────────┐
│  承接上篇 / 抛出核心问题 / 先说结论          │
│  深底 callout:把核心问题摆出来              │
└─────────────────────────────────────────────┘
                    │
                    ▼  ━━━ 板块分界线 ━━━
                    
┌─ 2 · 问题诊断 ──────────────────────────────┐
│  旧逻辑公式 vs 新逻辑公式(用两种 callout)  │
│  一句话总结差异                              │
│  接案例一句话铺垫                            │
└─────────────────────────────────────────────┘
                    │
                    ▼  ━━━ 板块分界线 ━━━
                    
┌─ 3 · 核心方法论(主体干货) ─────────────────┐
│  N 个维度(默认 5 类信息)                    │
│  每维度:它是什么 → 为什么 AI 需要它 →       │
│           错误示范 vs 正确示范                │
│  最后一维加 ★ 标记:90% 卖家漏的             │
└─────────────────────────────────────────────┘
                    │
                    ▼  ━━━ 板块分界线 ━━━
                    
┌─ 4 · 真实案例 ──────────────────────────────┐
│  脱敏客户名 + 诊断发现 + N 项改写动作 +     │
│  改写后效果(定性或允许公开的数字)           │
└─────────────────────────────────────────────┘
                    │
                    ▼  ━━━ 板块分界线 ━━━
                    
┌─ 5 · 但是,先别恐慌(冷静判断) ─────────────┐
│  数据钩子(YouGov / 行业调研)               │
│  Cosle 解读 → 结论 callout                  │
│  「不用大改,但要小改」过渡到行动            │
└─────────────────────────────────────────────┘
                    │
                    ▼  ━━━ 板块分界线 ━━━
                    
┌─ 6 · 行动建议 + 文末引流 ──────────────────┐
│  3 件今天能动手的事(各一个 callout 卡)     │
│  公众号:扫码 CTA + 下期预告                 │
│  小红书:仅品牌签名段,无 CTA                │
│  品牌签名段(深底盒,价值主张原文)           │
└─────────────────────────────────────────────┘
```

## 每节字数预算

| 节 | 公众号长文 | 小红书图卡(1 张约) |
|---|---|---|
| 摘要 | 80-120 字 | — |
| 1 · 开篇钩子 | 200-300 字 | 第 1 张(封面) |
| 2 · 问题诊断 | 300-400 字 | 第 2 张 |
| 3 · 核心方法论 | 1000-1500 字(每维度约 200-300) | 第 3-8 张 |
| 4 · 真实案例 | 400-500 字 | 第 9 张 |
| 5 · 泼冷水 | 300-400 字 | 第 10 张 |
| 6 · 行动 + 引流 | 200-300 字 | 第 11 张(行动 + 签名) |
| **合计** | **2500-3000 字** | **11 张** |

短钩子文(1200-1500 字)可以合并 2+3 节,跳过 5 节;但 1、4、6 节必须保留。

## 每节的「钩子」(开头第一句)写法

| 节 | 钩子句式 |
|---|---|
| 1 · 开篇 | 「上一篇我们讲完 X,公众号后台陆续收到不少卖家的同一个问题——……」 |
| 2 · 问题诊断 | 「过去 20 年,卖家围着 X 转。到了 Y 时代,公式变了:」 |
| 3 · 方法论 | 「我们把它叫做「N 类信息维度」,逐个来讲。」 |
| 4 · 案例 | 「上一篇我们讲过那个 X 卖家(脱敏沿用),诊断时发现 X% 的购买……」 |
| 5 · 泼冷水 | 「讲到这里,Cosle 必须给出一份冷静的判断——这也是我们一直坚持的『快速变化中的认知』。」 |
| 6 · 行动 | 「回到开头那个问题:X 到底要改什么?答案是:……」 |

## 每节的视觉部件(对应 HTML 模板)

| 节 | 必用部件 |
|---|---|
| 摘要 | `<section style="border-left:3px solid #e63946; background:#fafafa">` |
| 1 · 开篇 | 1 个深底 callout(把核心问题做大字反白) |
| 2 · 公式 | 2 个上下边框 callout,旧公式黑边框、新公式红边框 |
| 3 · 方法论 | N 个维度,每个含「灰底 ✗ 错误示范」+「暗红底 ✓ 正确示范」 |
| 4 · 案例 | 1 个浅灰底 callout 显诊断发现 + 列表显改写动作 + 1 个上下红边框 callout 显结论 |
| 5 · 数据 | 数据点用大号红字 + 灰底盒列;结论用深底 callout |
| 6 · 行动 | N 个浅灰底卡片(带红色左边条);文末黑底 CTA(扫码二维码);深底品牌签名段 |

## 板块分界线

公众号 HTML 里用统一的视觉分界线:

```html
<section style="text-align:center; margin:48px 0;">
  <span style="display:inline-block; width:30px; height:1px; background:#999; vertical-align:middle;"></span>
  <span style="display:inline-block; margin:0 16px; color:#666; font-size:12px; letter-spacing:3px;">COSLE</span>
  <span style="display:inline-block; width:30px; height:1px; background:#999; vertical-align:middle;"></span>
</section>
```

或者纯文本版用 `━━━━━━━━━━━━━━━━━━━━`(发布版 markdown 用这个)。

## 标题模板(用户决策前的 3 选 1)

写完正文后,给用户 3 个标题选项让选:

| 类型 | 句式 | 例子 |
|---|---|---|
| 直球结论型(推荐) | 「[场景],你的 X 到底要 Y」 | AI 购物时代,你的 Listing 到底要改什么 |
| 问句钩子型 | 「[现象]?一篇文章说清」 | Rufus 退役了?其实只是收编 |
| 数据冲击型 | 「[百分比] 的卖家漏了 [N] 类信息」 | 88.9% 的订单被 Rufus 答错,改了 5 类信息后……」 |

不允许的标题风格:
- ❌ 标题党(「重磅!」「紧急!」)
- ❌ 焦虑营销(「再不做就完了」「最后机会」)
- ❌ 戏谑梗(「Rufus 笑死了」「亚马逊神仙打架」)
