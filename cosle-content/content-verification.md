# 内容核查铁律

> 落稿后、生成 HTML / 图卡 / 封面之前必跑这套核查。任何一条不过关都要回头修正,**不允许带病发布**。

## 一级铁律(违反 = 立即停止 + 修正)

### 1. Listing 数字 100% 真实

源头规则在 memory:`feedback_listing_verification.md`(2026-05-14 用户明确)。

| 数字类型 | 处理方式 |
|---|---|
| 客户允许公开的(如 88.9% 浴室扶手案例) | 沿用,但每篇都要再次和用户确认是否继续公开 |
| 已发布过的(在前序文章里出现过) | 沿用 OK,数字必须和前文一字不差 |
| 改写后效果数字(命中率提升 X%) | 默认用定性描述「显著上升」,具体数字不公开 |
| 调研 / 论文数据(YouGov、SIGMOD) | 必须标注来源 + 年月,可追溯 |
| 用户口头提到但未文档化的 | 用 `[X]` 占位,在文末「待用户确认事项」列出 |

❌ **绝对禁止**:
- 编造数字(「大约 30%」「几乎所有卖家」)
- 把 A 客户的数字套到 B 客户
- 「我们看到很多卖家」却没有真实样本依据
- 改写 SIGMOD 论文里的实测数字

### 2. 价值主张段(60 字)一字不差

公众号长文末尾「关于 Cosle」灰盒、小红书第 11 张、HTML 文末品牌签名段,全部必须出现这段:

> 过去 20 年,卖家拼的是关键词、Review、出价。AI 购物时代,卖家拼的是 AI 怎么理解你的产品。Cosle 是这一侧的研究团队——我们告诉你:你的产品在 AI 推荐里到底被不被看见、被怎么描述、怎么改、怎么投广告。

不允许:
- 改写措辞(「20 年」改「这些年」)
- 增减分句
- 调整顺序

### 3. 禁用词 0 出现

### 4. 小红书绝不出现的内容

平台违禁:
- 二维码(任何形式,包括用户截图)
- 微信号 / WeChat / 「+V」/「VX」
- 「加我」/「扫码」/「私信」/「关注公众号」
- 跨平台导流(「公众号回复 XX」)
- 具体 ASIN 编号 / 客户品牌名 / 客户姓名

允许:
- 「Cosle 跨境卖家实验室」作为内容创作者署名
- 「关于 Cosle」品牌简介段(纯介绍,不带 CTA)
- 行业数据来源标注(YouGov 等)

### 5. 系列承接

每篇必须满足:
- 顶部有正确的系列编号(`#001` / `#002` 递增,不跳号)
- 开篇钩子引用上一篇的结论或预告
- 文末「下期预告」明确具体,下一篇要兑现
- reference-examples/ 里能追溯到所有已发布的标杆

## 待用户确认事项 · 落稿后必输出

落稿的 markdown 主稿末尾必须加一段「待用户确认事项」,把所有未对齐的假设列出来,等用户逐项过目。模板:

```markdown
---

## 待用户确认事项(发稿前必须 review)

1. **数字 X**:沿用上篇 vX 的口径,如果客户对外不希望再次出现,告诉我替换成定性描述
2. **数据来源 Y**:来自参考文章「XX」,如果希望换更权威的来源,告诉我我替换
3. **下一期预告**:暂定「YYY」,如果想换主题,告诉我
4. **真实改写效果数字**:正文用了「显著上升」+「具体数字在客户诊断报告里」的定性描述以规避编造红线,如果你有真实可公开数字,告诉我我补回
```
